- Collections are persistent per-user named sets of folders. A user creates a collection from the Collections page, selects one or more immediate folder cards in Gallery, and adds the selection to the chosen collection. Membership can span different parent locations under that user's configured root and can be edited later.
- Normalize collection member paths and collapse overlaps: an existing parent already covers a proposed descendant, while adding a new parent removes redundant descendant rows. The owner is the only authenticated user allowed to create, edit, delete, share, or revoke that collection.
- Collection unlisted links use the existing cryptographically random, revocable share-token model. Their Gallery entry is a virtual root made from the selected folders; navigation and direct file endpoints remain limited to one of those selected roots and descendants. The collection name is the shared breadcrumb root, and Back from a selected root returns there instead of exposing an ancestor.
- Collection ZIP download streams directly to the response. Each selected folder is a distinct top-level entry, with numeric suffixes added when two selected folders have the same leaf name. Missing folders are skipped rather than widening access or failing into an unrelated path.

## Gallery product requirements

- Opening a gallery lists immediate child folders and files.
- Support Grid and List views; the first-use Grid default is 8 items per row, while the selected view and later Grid items-per-row remain persisted in browser local storage.
- Sorting is available from the header for name, size, and modified date in ascending or descending order. Persist the last normalized sort field/direction for one year in HttpOnly, SameSite=Lax cookies scoped to the application's PathBase, and restore them whenever a private or shared Gallery URL does not explicitly supply sort parameters.
- Images use cached WebP thumbnails in the browser view. Load the original only in the full-image viewer or for download.
- Cached thumbnails return immediately. Missing thumbnails go through a singleton High/Normal dispatcher with a 256-job pending bound. The Admin-configured concurrency range is 1–16 (default 2); visible requests are High priority and active generation never starts above the current limit.
- Thumbnail `<img>` elements carry `data-thumbnail-src`. `IntersectionObserver` submits only visible images to a browser dispatcher capped at 12 simultaneous low-priority same-origin fetches so cached folder-cover tiles are not serialized in groups of four. `AbortController` cancels unfinished requests after scrolling away. Before unmodified link navigation or form submission, clear pending work and abort all active thumbnail fetches synchronously, with delayed resumption only if the current document remains active; this cancellation is what keeps navigation responsive at the higher cap. `pagehide` cancels without resumption. HTTP 503 queue-full responses retry only while the image remains visible. Browsers without IntersectionObserver use the same bounded dispatcher rather than direct unlimited image URLs.
- Because each folder card can contain four tile URLs, visible folder-cover images first perform a parallel `fetch` using `mode: same-origin` and `cache: only-if-cached`. A successful HTTP-cache response is decoded from its Blob immediately and bypasses the 12-slot dispatcher; a 504 cache miss, unsupported-mode exception, or other probe failure falls through to the normal bounded fetch. Track one probe attempt per image so a miss cannot loop. These probes must remain cache-only: server/network work continues to use the cancellable dispatcher and bounded ImageSharp queue.
- Thumbnail URLs carry `v=<algorithm-version>` plus `stamp=<UTC-modified-ticks>-<source-length>` for regular images and every direct-child folder-cover tile. Fingerprinted responses are private immutable browser-cache entries for one year; requests without a stamp require revalidation. A source content timestamp/length change or an algorithm-version bump therefore changes the URL instead of serving a stale browser entry. The existing disk-cache identity remains the final authority and includes the same source metadata plus configured thumbnail dimensions/quality.
- Deferred image elements remain visually hidden until their actual `load` event. Retro Grid/List media and folder-cover tiles keep the dark pixel-theme stepped scan. Modern uses its own smooth low-contrast skeleton shimmer with transform-only motion, paint containment, and a static reduced-motion fallback so its loading state matches the theme without adding scroll-heavy effects. Both themes reveal the decoded WebP with a short opacity transition; a genuine terminal fetch/decode failure replaces the loading state with an error mark instead of browser broken-image chrome or filename alt text.
- Non-image files remain downloadable and use an extension label instead of a thumbnail.
- Hide entries carrying Windows `Hidden` or `System` attributes (including inaccessible entries such as `System Volume Information`) across the complete file surface. Also ignore `Thumbs.db` and the common singular `Thumb.db` spelling case-insensitively: omit them from private/shared Gallery listings and folder-cover collages, reject them as collection/share roots and direct file/thumbnail/selected-download requests, and skip them in recursive streamed folder ZIPs. Attribute/enumeration failures are treated as hidden so protected metadata cannot leak or abort a ZIP.
- Users can enter child folders, download one file, or stream the current folder and all descendants as ZIP without a server-side temporary ZIP.
- Every folder under a user's configured root is private and requires that user's application login. There is no public mode and no per-folder visibility selector.
- The Share button creates a revocable unlisted token for the current folder. The token can navigate only within that folder and its descendants. Its breadcrumb starts with the shared folder name, omits `Home` and ancestor paths, and its back navigation stops at the shared folder. At creation, persist the current normalized sort/direction plus client-side items-per-row and Grid/List mode on that `ShareLink`. Render all managed share URLs with `sort`, `dir`, `itemsPerRow`, and `view` query values. On the recipient's first render, valid explicit query values override localStorage and are then saved by the existing controls, so subsequent navigation follows the recipient's latest changes. Existing links upgrade to Name Ascending, 8 per row, Grid defaults. After a successful create, return with the Share panel already expanded and highlight the new URL row so its Copy button is immediately usable; normal later visits keep the panel collapsed.
- The Gallery content uses almost the full viewport width and does not display the user's name as a large page heading.
- The complete application UI uses English for application-owned copy, including Gallery, login, admin, sharing, errors, validation, confirmations, accessibility labels, and JavaScript feedback. Do not alter user-controlled file/folder names, display names, or the configured site title.
- Login brute-force protection is layered. Identity records 5 failed attempts against a real user in SQLite and locks it for 15 minutes. A bounded, hashed-key in-memory sliding-window limiter independently applies the same 5-per-15-minute cooldown to normalized usernames (including nonexistent names) and 12 failures per client IP over 5 minutes to slow password spraying. A blocked POST renders the normal themed Login view as HTTP 429 with `Retry-After` and a live countdown. Do not disclose which limiter fired or whether the username exists. Direct IIS deployments key the IP bucket from `RemoteIpAddress`; only switch to forwarded client addresses after explicitly trusting a known reverse proxy.
- Invalid Share entry requests use a separate bounded, hashed-IP sliding-window limiter. Malformed, unknown, and revoked 48-hex-character tokens return 404 for attempts 1-19; attempt 20 within 5 minutes and subsequent requests during that window return a themed 429 response with `Retry-After` and the generic countdown. Check an active cooldown before the database lookup. Valid tokens are not counted; a valid token combined with a path outside its share scope remains a normal 404 rather than token-enumeration evidence.
- Visual theme is an administrator-managed system setting. `Retro` remains the default/current theme and loads `site.css`, retaining the FileListing-inspired dark navy pixel-grid surfaces, Cascadia Mono/Consolas typography, cyan/blue/pink/yellow accents, square controls/cards, two-pixel outlines, and hard offset shadows. `Modern` loads `site-modern.css`, which is the shared functional/base layout without the 300-line Retro override block plus modern color, typography, background, folder-shell, radius, and shadow refinements. The layout emits `theme-retro` or `theme-modern` on `<body>`. Missing or invalid database values fall back to Retro. Do not place a foreground scanline overlay across thumbnails or folder-cover images in either theme.
- Modern performance invariants: avoid `background-attachment: fixed`, remove backdrop blur from the header, sticky Gallery toolbar, and repeated selection controls, and avoid blur-radius shadows on every folder in large collections. Prefer opaque surfaces and zero-blur offset shadows so scrolling does not trigger expensive full-page/per-card repaints. The Modern folder tab uses a 2px border aligned at `left: -2px`; the shell radius is `0 10px 10px 10px` so the tab joins the square top-left body corner without a one-pixel protrusion.
- The top-left brand uses the `AppTitle` value editable under Admin system settings; the default is `Gallery`.
- File thumbnails preserve the complete image ratio inside the media box in both Grid and List views. ImageSharp uses `ResizeMode.Max` so the cached WebP itself retains the full source image. For regular image buttons, CSS absolutely positions the image with `inset: 0`, gives it the media box's definite 100% width/height, and enforces `object-fit: contain !important`. A relative grid item with intrinsic portrait dimensions is prohibited because percentage max-height can remain unresolved against an aspect-ratio grid track and the media overflow then crops it. Empty space is preferable to cropping, and hover must not scale regular image thumbnails beyond the box. Folder-cover collage tiles may still use their dedicated cover crop.
- Include one explicit thumbnail-algorithm version in every server cache identity and thumbnail request URL, and increment it when resize, orientation, or encoding behavior changes. This invalidates incompatible cached WebPs in both the server and browser by generating new keys/URLs without destructively clearing the shared cache.
- Folder covers use a 1-to-4 tile collage from direct child images only, with lazy thumbnail requests and no recursive folder scan. The collage sits inside a clearly recognizable pixel-art folder shell (top tab, yellow outline, dark-gold body, and hard shadow), while the directory card uses a distinct folder-colored border; never present the four images as an unframed full-card collage. Anchor the shell with small fixed Grid/List edge insets so the tab and shadow stay inside the unpadded media box while the cover occupies almost all available thumbnail space; large percentage gutters are not permitted. Keep zero minimum dimensions and clip only the inner collage grid so portrait/landscape intrinsic sizes cannot move or enlarge the shell.
- Each current-folder file has a selection control. `Download selected` is disabled at zero, returns the original for one selection, and streams a ZIP for multiple selections.
- Folder ZIP, selected-file, and full-viewer Download actions show the shared inline SVG download icon beside their English labels.
- In Grid view, single-clicking an image selects it exclusively, Ctrl+click toggles additive selection, Shift+click replaces all old selections with the range from the last selection anchor, Ctrl+Shift+click adds that range while preserving old selections, and double-click opens the original-image viewer. Checkbox interaction remains an independent per-file toggle.
- In List view, the checkbox occupies its own column and must not overlay the thumbnail. Clicking a file name downloads that file.
- Full-image viewing preserves original-size initial behavior: small images start at native dimensions; oversized images are sized from the viewer's actual available width and height. Mouse click toggles Fit/1:1 while preserving the clicked image-coordinate ratio under the pointer. Touch Pointer Events provide continuous two-finger scaling from Fit through 4x native size, one-finger panning while zoomed, and double-tap centered at the tap point. Double-tap toggles Fit/1:1 for oversized images and native/2x for already-fitting images. Suppress the synthetic click after touch so one tap cannot accidentally invoke the mouse toggle. Center the image on any axis that does not overflow, do not expose a separate zoom button, and show a download icon beside the viewer's Download label.
- The full viewer does not generate a medium preview. Original-view URLs carry the source length/UTC-modification fingerprint and fingerprinted responses are private immutable for one year. Completed full-image Blobs/object URLs enter a page-lifetime LRU capped at 4 entries and normally 256 MB; a single entry may exceed the byte cap, while older entries are evicted/revoked. Previous/next revisits consult this LRU first and show the decoded full image directly. If absent, the browser performs same-origin `fetch` with `cache: only-if-cached` while leaving both stage placeholder and progress hidden. On a miss, `ViewFile` calls ImageSharp `IdentifyAsync`, swaps dimensions for EXIF orientations 5–8, and returns them in `X-Image-Width`/`X-Image-Height` before streaming the body. The XHR `HEADERS_RECEIVED` handler records those dimensions and only then starts the existing thumbnail. Placeholder width/height are the exact `min(1, available/original)` result from the original dimensions, so a 1920px landscape on a wider screen remains 1920px instead of being incorrectly enlarged from a bound-hitting 480px thumbnail. The configured thumbnail-bound heuristic remains only as metadata-failure fallback. Placeholder sizing reruns on viewport resize and does not enable zoom. XHR progress shows `percentage · loaded bytes / total bytes`. A browser-cache hit is decoded/displayed without a thumbnail flash. Per-view generation plus AbortController/XHR abort prevents stale replacement; navigation no longer revokes reusable full-image Blob URLs, which are revoked only on replacement, LRU eviction, or `pagehide`. Gallery thumbnail fetches remain suspended while the dialog is open and resume on close.
- Full-viewer previous/next navigation uses the current page's image-button order, skipping folders and non-image files. Slim edge buttons and keyboard Left/Right arrows both wrap cyclically; controls remain hidden for zero or one image. Changing images resets zoom and scroll before fitting the new original.
- Parent navigation includes a normalized `focus` query value for the folder being left. On the parent page, match it against rendered directory `data-relative-path`, center that card with `scrollIntoView`, and apply a temporary return-focus highlight. Invalid or unmatched focus values are ignored.
- The site header scrolls away normally. The Gallery toolbar is sticky at `top: 0` and takes the top edge after the header leaves the viewport, without causing horizontal overflow.



## Technology decisions

- .NET 10 is appropriate because it is the installed LTS runtime and provides the ASP.NET Core authentication and streaming stack required by the application.
- SQLite is appropriate for the single-server IIS deployment and relatively small transactional configuration/identity workload. Keep gallery files and generated media outside the database.
- ASP.NET Core Identity provides password hashing, cookie authentication, roles, and password reset operations.
- ImageSharp 3.1.12 creates WebP thumbnails. ImageSharp 4 was rejected because it requires a Six Labors build-time license key. Pin `SQLitePCLRaw.lib.e_sqlite3` 2.1.12 or newer to avoid the vulnerable transitive native package previously selected by restore.

## Filesystem identity and OneDrive

- IIS reads user gallery roots as its worker identity, not as the signed-in Gallery user or the Windows desktop user.
- User-profile and OneDrive roots therefore require an explicit `IIS_IUSRS` Read & Execute ACL on the selected root and descendants.
- Keep access read-only. The application writes thumbnails and SQLite state to `C:\Web\imagegallery-data`, not to the user's image root.
- ASP.NET Core Data Protection uses a persistent filesystem key ring at `Gallery:DataProtectionKeysPath` (`C:\Web\imagegallery-data\keys` in production) with application name `WebGallery`. This key directory is deployment state and must retain its files across app-pool restarts and deployments; the IIS app-pool identity needs Modify access. A first deployment of this fix invalidates cookies created with the previous ephemeral key ring once, after which the 14-day sliding authentication cookie survives normal deployments.
- Admin root-folder save now checks that the directory exists and can be enumerated, returning an English validation message for missing, inaccessible, or invalid paths.
- For OneDrive, pin gallery files locally with **Always keep on this device** before depending on unattended IIS delivery.
