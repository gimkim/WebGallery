- Request: runnable NAS capability and stage-performance comparison for libjpeg-turbo and Intel iGPU JPEG decoding.
- Added standalone tests/JpegHardwareBenchmark project (Program.cs, Turbo.cs, Runner.cs, README.md, DEPENDENCIES.md). No web application code/settings changed. Updated AGENTS benchmark isolation/timing rules.
- Methods: existing ImageSharp IDCT, native TurboJPEG full and DCT-scaled RGB, forced QSV decode-only diagnostic, QSV decode/download/RGB and QSV decode/VPP downscale/download/RGB. All thumbnail-producing methods share final CPU EXIF orientation/Lanczos resize/WebP quality. Reads/header metadata/import/final processing/encoding/write are separate. GPU process stages are explicitly combined rather than presented as pure hardware decode time. Failures never silently fall back to CPU.
- Capability suite: generated 2400x1600 baseline and progressive EXIF-rotated JPEGs, actual native full/scaled decode, forced QSV device/decoder execution and output sizing, FFmpeg codec/filter/build inventory, Windows GPU/driver inventory. Per-image subprocesses are timed out and output bounded. Original files/settings read-only, unique output directories; incremental reports retain failed rows. Native paths reuse original EXIF metadata. Reports have file paths and must be treated as private.
