# Background thumbnail creation

- Date: 2026-09-08 17:32 Asia/Bangkok.
- Request: Automatically create thumbnails through every configured root with configurable workers and no races/conflicts with on-demand generation.
- Added BackgroundThumbnailService: opt-in workers 0–16 in Management, SQLite persistence/startup restore, live settings changes, snapshot status, bounded recursive enumeration over all user roots, 10-minute interval after each completed pass, current root ownership/path revalidation per image. Missing/inaccessible/hidden/system/metadata/link entries are skipped. Cache directory is excluded even inside a whole-drive media root. Existing cached files are reused. Cancellation propagates on settings changes and shutdown.
- Extended shared ThumbnailWorkQueue with Background priority after Visible and Normal, independent background cap inside the existing total concurrency ceiling. The scanner submits at most its worker count and retries queue saturation with cancellable backoff. Already running generation is not preempted by foreground arrival.
- Fixed ThumbnailService's removable semaphore race: 1024 permanent bounded lock stripes are acquired inside dispatched operations, so queued background requests cannot hold a lock ahead of visible work. All paths use the same cache key, locked recheck, unique temporary output and atomic rename. Recheck source length/modification before publication and clean partial outputs on failure/cancellation.
