# Stop drive-root duplicates reappearing

- Request: a named drive root E:\ produces a second E: entry that returns after removal.
- Root cause: startup's INSERT OR IGNORE seeded every user's legacy RootFolder on every start and used SQLite rtrim, changing E:\ to E:. The unique path index therefore did not match the correct existing root.
- Fix: transactional one-time Migration.UserRoots.SeededV2 marker, seed only owners with no roots and preserve the full path. Bootstrap default root is now created only for a new admin, not when an existing admin intentionally has zero roots. Existing root IDs/names/shares remain untouched; owners can remove an existing malformed duplicate once without it reappearing.
- Files: DatabaseInitializer.cs, RootMigrationHarness, AGENTS.md and project notes.
- Validation: actual SQLite harness passed drive-root preservation, existing-root retention, duplicate removal across repeated migrations and empty roots with stale legacy values. Build and Windows-IIS publish passed. No interactive Management UI test.
- Deployed to Windows NAS 192.168.1.29 via SMB only. App backup at web-data/backups/20260908-151042-root-seed-fix, temporary app_offline removed after copy. Published files match deployed SHA256; appsettings.json/web.config match backup; LAN-pinned TLS health status ok. Production database not replaced; app startup performs only the migration marker/eligible legacy seeding. Linux target untouched. Existing ghost rows not automatically deleted.
