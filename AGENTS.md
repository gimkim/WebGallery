## Application architecture

- Folder sort preferences persist in SQLite FolderBrowsePreferences per authenticated owner and normalized logical folder key; Windows keys ignore case, Linux retains case. Explicit valid sort/direction override saved values; private folder/back/breadcrumb navigation omits inherited sort. Chunk fetches retain current order but do not write preferences. Shares retain their own presentation rules and never write owner preferences. Additive idempotent schema; no index/cache reset.
- Infinite scroll loads earlier ranges automatically when the upper sentinel approaches the viewport, including short jump windows. Retry button appears only on failure. Anchor the existing first card after prepend (not its display:contents wrapper), disable browser scroll anchoring on the grid to avoid double compensation, and preserve loaded selection.

- Selection tools are additive: keep the navigation/search/sort/density/view/folder-action row visible and in the same position when selecting files. Display selection actions underneath; never hide the primary toolbar or mobile compact summary due to selection. Desktop uses fixed two-column toolbar tracks with selection spanning a separate row.

- Large-folder browsing uses internal 500-item HTML chunks with infinite append, explicit load-earlier on jump windows, and a compact authorized BrowseManifest endpoint containing only contiguous sort sections (label, offset, count), total/page size/revision. Do not return per-file metadata in this manifest. Date sorts render month/year headers; rail links retain real page/hash URLs for new tabs. Append binds new cards to existing thumbnail/viewer/selection/write handlers without remounting the document. Reject mismatched listing revisions instead of mixing reordered ranges; keep selection while appending. Manifest is no-store and uses the same owner/share-scope checks. Name/modified/size revisions ignore unrelated Date Taken backfill.

- Date Taken indexing now defaults to4 configurable workers (1–16), persisted as AppSettings.DateTakenWorkers through Admin-only antiforgery SaveIndexingSettings. Apply after save without restart; lowering lets active reads drain. A bounded128-entry coordinator keeps identities held until commit, prepares64-entry pages, refills free reader slots continuously, and writes up to32 results per transaction through one separate writer (flush partial results within roughly500ms). Each reader/query/writer owns its DbContext. No20ms per-file throttle or batch-wide read barrier. Preserve viewed-folder priority, source fingerprint checks, retries, cancellation and pending work on restart. This supersedes earlier single-reader guidance.

- JPEG Date Taken production reader now uses JpegDateTaken: sniff SOI, read only APP1 Exif TIFF, seek other segments and stop before SOS. Bounded4096 segments/padding,4MiB total APP1,16-bit segment length; validate TIFF endian/magic/counts/offsets and traverse only IFD0 -> Exif IFD. Do not decode pixels or scan compressed body. Missing EXIF returns unknown; malformed/truncated JPEG follows metadata retry handling. Non-JPEG ImageSharp and RAW ExifTool paths are unchanged; do not claim their I/O was optimized. Keep existing dates/index/cache; pending work uses new reader without re-index-all.

- 2026-09-17 diagnostic correction: ImageSharp3.1.12 Image.IdentifyAsync avoids pixel decoding but measured JPEG stream reads cover the entire file. Do not describe it as EXIF-only I/O. tests/MetadataReadAudit compares counted stream reads with APP1-only JPEG extraction (ExifProfile consumes TIFF bytes after six-byte Exif prefix). Diagnostic harness is not a hardened production parser; production DateTakenIndexer still uses Identify until separately replaced/tested.

- Date Taken fallback update: keep dated files first, ordered by capture date; undated files follow, ordered by Date Modified in the selected Asc/Desc direction. Filename is only the tie-breaker within equal dates. Preserve folders-first convention and sort the complete folder before pagination. This supersedes the earlier filename-only ordering for missing dates; it does not invent or persist a capture date.

- The Admin system settings page manages AppTitle, thumbnail concurrency and reduced-JPEG decoding, plus login-security controls. Persist settings in SQLite and update their live runtime snapshots on save. Theme is no longer read, saved or exposed.
- A configured user root must already exist and be enumerable by the IIS worker identity. Validate access during Admin save and show a useful error instead of allowing a later Gallery 500. Adding a root must never fail silently: probe Windows attributes and one directory enumeration so missing paths, file-not-directory input, access denial/security policy, unsupported paths, and other I/O failures produce distinct English explanations. Catch and log database-save failures, translate common SQLite busy/locked, read-only, disk-full, and constraint errors, then redirect back to the affected user card and repeat the cause in an alert beside that user's Gallery folders form.
- For roots inside a Windows user profile or OneDrive, grant `IIS_IUSRS` only the required Read & Execute permission on the selected root and descendants. Do not grant write/delete permission merely for gallery browsing.
- OneDrive gallery content should be marked **Always keep on this device**; an IIS worker cannot reliably serve cloud-only placeholders when the interactive OneDrive session is unavailable.
- A fresh database creates `admin` with a random password in `C:\Web\imagegallery-data\bootstrap-admin.txt`. Never commit or place a bootstrap password in source configuration.
- Protect the application Login POST with administrator-managed runtime settings stored in SQLite: failed attempts before progressive username delay, seconds added per further failure, username failures before cooldown, username cooldown minutes, client-IP failures before cooldown, and client-IP cooldown minutes. Defaults are delay after 3 failures with 2 seconds added per further failure, username cooldown after 5 failures for 15 minutes, and IP cooldown after 12 failures for 5 minutes. Management saves must validate bounded values and apply them immediately without an application restart. The bounded in-memory limiter uses hashed normalized-username/IP keys for delays and cooldowns; ASP.NET Identity separately persists the configured real-account username cooldown across restarts. Existing active persistent account lockouts retain their recorded expiry when settings change. Return the styled Login view with HTTP 429, a `Retry-After` header, and a visible countdown; keep the message generic to avoid confirming whether an account exists. Successful authentication clears the current username/IP buckets. Use the direct connection IP unless a reverse proxy is deliberately configured with trusted forwarded-header processing; never trust arbitrary client-supplied forwarding headers.
- Protect the public Share entry-point from token enumeration. Invalid, malformed, missing, or revoked tokens count case-insensitively by direct client IP; attempts 1-19 return the same 404, while attempt 20 within a sliding 5-minute window starts a 5-minute cooldown. During cooldown return the themed HTTP 429 page with `Retry-After` and the shared countdown UI before querying SQLite. Keep the bounded limiter keys hashed and do not reveal whether a particular token existed. A valid token with an out-of-scope path remains a normal 404 and does not count as token guessing.

## IIS requirements

- Legacy RootFolder seeding is a one-time transaction marked Migration.UserRoots.SeededV2. Seed only users with no UserRoots, preserve the physical path including volume-root separators, and never recreate deleted assignments on startup. Bootstrap's default root applies only to a newly created admin. Do not automatically delete old malformed duplicate root IDs because shares/collections may refer to them; after the fix, owners can remove them permanently.

- JPEG accelerator experiments live in tests/JpegHardwareBenchmark and deploy only to NAS web-tools/jpeg-hardware-benchmark, never the IIS application. Force QSV hardware selection with no CPU fallback; distinguish decoder listing from real decode/output capability. FFmpeg timings combine startup/device/decode/transfers (and optional VPP), not isolated GPU kernel times. Keep settings/media read-only, errors and paired outputs in unique results directories, and include official native dependency licenses/checksums.

- Grid thumbnail Blob URLs are revoked after load. Never assign those URLs to the viewer: snapshot the already-decoded same-origin thumbnail pixels into a small canvas/data URL, with a thumbnail-endpoint fallback if unavailable. Test this in a real browser with an explicitly revoked Blob, not only mocked image objects.
- Viewer Info fetches EXIF on demand through ImageMetadata, using the same private/share exact-file access resolution as ViewFile. Read headers only, allowlist camera/lens/date/exposure/ISO/focal-length/software fields, omit GPS/serial/maker notes, render values as text, and cancel/ignore stale responses on navigation or close. No EXIF is a normal explicit empty state.

- Viewer cache entries may contain encoded prefetched Blobs rather than decoded pixels. Start the thumbnail placeholder before every original-load path, including memory Blob hits, so large originals never intentionally wait for decode on an empty stage.

- Updated viewer loading preference: show an enlarged thumbnail immediately while probing/loading the full image, reusing the grid's decoded image/Blob when possible. This supersedes the earlier empty-stage-before-headers requirement. Preserve aspect ratio, disable placeholder zoom, refine dimensions on original headers, and keep full-image memory-cache hits direct.

- Management's ThumbnailDecodeMode persists `full` (default) or `jpeg-idct` in AppSettings. Reduced JPEG decoding uses ImageSharp IDCT-only with a square max-dimension target before AutoOrient and final Lanczos3 Max resize. Other formats retain full decoding. Use distinct server/browser cache versions (`contain-v1`, `contain-idct-v1`); honor the requested recognized version for in-flight pages when settings change. Never replace the production database to change this setting.

- Preserve filesystem volume roots with `Path.TrimEndingDirectorySeparator`, never turn `U:\` into drive-relative `U:`. Windows volume-root Hidden/System attributes must not hide an authorized root; child entries still use the normal hidden/system, metadata, and link filters.

- The `/Gallery` IIS application must allow Anonymous Authentication and disable Basic Authentication so ASP.NET Core can enforce login-protected galleries and token-based share links itself.
- IIS authentication settings are locked at server level on the current machine and cannot be overridden in `web.config`; change them for the `/Gallery` application with IIS Manager or elevated `appcmd`.
