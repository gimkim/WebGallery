## Application architecture

- The application targets .NET 10 LTS and ASP.NET Core MVC.
- SQLite stores ASP.NET Identity users/roles, revocable unlisted share links, system settings, and legacy folder-rule rows retained for schema compatibility. Do not store original images or generated ZIP archives in SQLite.
- Each user has an administrator-configured filesystem root. Every requested path must be normalized and verified to remain under that root.
- Original files remain in their configured roots. WebP thumbnails are generated on demand under `C:\Web\imagegallery-data\cache` and keyed by a thumbnail-algorithm version, source path, size, modification time, and thumbnail settings. The same version must appear in the browser thumbnail URL. Increment it whenever resizing/orientation/encoding semantics change so incompatible server and browser cache files cannot survive a deployment.
- Thumbnail cache hits bypass generation. Cache misses enter one application-wide bounded priority queue: at most 256 jobs may wait, visible-image jobs run before normal jobs, and active ImageSharp generation must never exceed the administrator's `ThumbnailConcurrency` setting (1–16, default 2). A reduced limit applies to new starts without forcibly terminating already active work.
- Browser thumbnail loading is visibility-driven. Use `IntersectionObserver` and a client-side dispatcher capped at 12 simultaneous low-priority `fetch` requests so large folder-cover grids can consume cache hits quickly. Do not request off-screen thumbnails. Abort unfinished requests when their image leaves the viewport so queued work is skipped and active ImageSharp work receives cancellation. Before a normal link navigation or form submission, synchronously clear pending thumbnail requests and abort active ones, preserving interactive navigation even with the higher cache-read concurrency; cancel without resume on `pagehide`. If a click/download leaves the document active, resume visible thumbnail scheduling after a short delay. Keep the same bounded dispatcher as the no-IntersectionObserver fallback.
- A visible folder-cover tile gets one parallel HTTP-cache-only probe (`cache: only-if-cached`, same-origin) before entering the 12-request dispatcher. Cache hits may render immediately without consuming dispatcher slots or making a network request; only probe misses/failures enter the bounded network/server queue. Never apply the unbounded probe to a mode that can contact the network. Browsers without `only-if-cached` support must safely fall back to the bounded queue. Navigation cancellation still governs all actual thumbnail network requests.
- Every thumbnail URL must include both the thumbnail algorithm version and a source fingerprint derived from source length and UTC modification ticks. Fingerprinted thumbnail responses use `Cache-Control: private, max-age=31536000, immutable`; legacy/unfingerprinted requests use `private, no-cache`. This lets browser Back and repeat visits reuse WebPs without network revalidation while source changes produce a new URL. Increment the algorithm version whenever thumbnail settings or processing semantics change.
- Deferred thumbnails must never expose the browser's broken-image icon or alt text as a loading state. Until the image `load` event succeeds, Retro renders its stepped pixel scan while Modern renders a separate smooth, subtle skeleton shimmer driven by compositor-friendly transforms; do not reuse the Retro animation in Modern. Respect reduced-motion preferences, reveal the image after load, and reserve a distinct error mark for genuine fetch/decode failure. Apply per-tile placeholders to folder-cover collages.
- Keep persistent production state outside the deployment directory: database/cache in `C:\Web\imagegallery-data` and the default content root in `C:\Web\gallery-content`.
- Persist ASP.NET Core Data Protection keys outside the deployment directory at `C:\Web\imagegallery-data\keys` (configurable through `Gallery:DataProtectionKeysPath`). Grant the IIS application pool Modify access to this directory. The application name is fixed as `WebGallery`, so authentication cookies and antiforgery tokens survive application restarts and deployments on the same machine; losing or replacing the key directory intentionally invalidates them.
- Every user's complete gallery tree is private and requires that user's application login. Do not expose a public mode or a per-folder access-mode selector.
- Sharing is available only through a revocable unlisted token created with the current folder's Share button. A token is restricted to its linked folder and descendants; the shared folder is the breadcrumb/navigation root and must not reveal or navigate to ancestors above it. Each share record captures the sort field/direction, Grid items per row, and Grid/List mode active when it is created. The displayed share URL must include those presentation values so a recipient's first render matches the sharer's view; explicit URL values take precedence over the recipient's saved browser preferences, while later recipient changes persist normally for navigation within that browser.
- A signed-in user may create persistent named collections and add multiple selected folders from different locations in that user's gallery tree. Collection membership stores normalized owner-relative folder paths; adding a parent removes redundant descendant memberships, and adding a descendant of an existing member is ignored. Collection management must allow adding/removing folders, deleting the collection, creating/revoking unlisted links, and copying a newly created link immediately.
- A collection share link opens a virtual root containing only the collection's selected folder cards. Recipients may enter each selected folder and its descendants, but cannot browse any owner path outside those roots. Back from a selected root returns to the virtual collection root. Downloading the collection streams one ZIP without a temporary archive and gives every selected folder a unique top-level ZIP directory name. Existing folder-only share behavior remains unchanged.
- After creating a share link, redirect back with the Share panel open, visibly highlight the newly created URL row, and keep its Copy button immediately available. Do not collapse the panel and force the user to reopen it to retrieve the link.
- Folder ZIP downloads must stream directly to the HTTP response without creating a temporary ZIP file. Skip reparse-point directories while recursively enumerating files.
- Treat Windows Explorer's `Thumbs.db` as ignored metadata, case-insensitively. Do not list it in private/shared Gallery views, include it in streamed folder ZIP downloads, or serve it through direct file/thumbnail/selected-download endpoints.
- Keep the Gallery page near full width with compact side padding; do not spend large horizontal or vertical areas on decorative whitespace or a large user display-name heading.
- The administrator selects one system-wide visual theme stored as the `Theme` app setting. `retro` is the default and preserves the established FileListing-inspired Cascadia/Consolas typography, dark navy grid, cyan/blue/pink/yellow accents, square corners, two-pixel borders, and offset pixel shadows. `modern` uses `site-modern.css` with Segoe UI-style typography, softer GitHub-dark colors, rounded cards/controls, subtle gradients, and soft shadows. Theme choice changes presentation only; all Gallery layout, thumbnail, selection, sharing, and viewer behavior must remain equivalent. Never apply a foreground scanline overlay across thumbnails or folder covers.
- `site.css` is the complete Retro stylesheet. `site-modern.css` is a mechanically derived copy of the shared/base rules with the Retro override block removed, followed by Modern-specific palette and component refinements. Any future functional layout or responsive CSS change must be applied and validated in both files; do not allow selecting a theme to change behavior or omit a later bug fix.
- Keep Modern scrolling suitable for large Grid/List galleries: do not use fixed page backgrounds, repeated per-card `backdrop-filter`, or large blurred shadows on every folder shell. The sticky toolbar and header use opaque/nearly opaque surfaces without backdrop blur; folder shells use cheap zero-blur shadows. In the Modern folder silhouette, align the tab at `left: -2px` with the 2px shell border and keep the shell's top-left radius square so the tab/body join has no protruding line glitch.
- All application-owned user-facing text, labels, messages, titles, accessibility labels, and tooltips must be English. User-controlled values such as file names, folder names, display names, and the configured `AppTitle` remain unchanged.
- The brand text comes from the administrator-managed `AppTitle` setting. Do not hardcode `Gim Gallery` in the layout; the configured default is `Gallery`.
- Regular image thumbnails in both Grid and List views must preserve the complete source aspect ratio end to end: ImageSharp generates them with `ResizeMode.Max`. In the browser, absolutely position the regular thumbnail against the image-button padding box (`inset: 0; width/height: 100%`) and enforce `object-fit: contain !important`; do not leave it as a relative CSS-grid item because intrinsic portrait height can overflow an aspect-ratio track and be clipped. Do not crop or hover-zoom regular thumbnails. Folder-cover collage tiles remain a separate cover treatment.
- A folder card may show up to four thumbnail tiles selected only from images directly inside that folder. Keep those tiles visibly contained inside a pixel-theme folder silhouette with a tab, contrasting border, and hard shadow so a collage cannot be mistaken for an image-file thumbnail. Absolutely position the shell against the fixed media box with small fixed edge insets so its outline nearly fills the thumbnail area; do not reintroduce large percentage gutters. Keep zero automatic minimum size so image intrinsic dimensions cannot resize or shift it. The complete tab, shadow, and bottom edge must remain inside the media area at every Grid density and in List view. Do not recursively search descendant folders for cover images; show the normal folder icon when none exist.
- File selection applies to files in the current folder. One selected file downloads directly; multiple selected files stream as a ZIP without a temporary archive. In Grid view, a single image click selects only that image, Ctrl+click toggles an additional image, Shift+click replaces the old selection with the range from the selection anchor, Ctrl+Shift+click adds that range to the old selection, and double-click opens the full viewer. The checkbox always toggles only its own file.
- Display the same inline download icon beside the label for full-viewer download, folder ZIP download, and selected-file download actions. Keep the icon embedded in markup/CSS rather than adding an external asset dependency.
- In List view, keep the selection checkbox in a separate column from the thumbnail and make the file name a direct download link.
- The full-image viewer must not upscale images smaller than the available viewport on initial display. Larger images start fitted to the viewer's available width and height. Clicking with a mouse zooms to original `1:1` pixels while keeping the clicked point under the pointer; clicking again returns to fitted view. On touch devices, support continuous two-finger pinch zoom (fit through 4x original), one-finger panning while zoomed, and double-tap zoom centered at the tapped point. Double-tap toggles Fit/1:1 for large images and native/2x for images that already fit. Do not show a separate zoom button. Show a download icon beside the Download label in the viewer action.
- Full-image viewing is progressive but must not create a separate medium-size preview rendition. Every original-view URL includes the source length/UTC-modification fingerprint and returns `private, max-age=31536000, immutable`. First consult a page-lifetime decoded/full-Blob LRU (maximum 4 entries and normally 256 MB total); revisiting a recent image through previous/next must display that full image directly without a thumbnail or cache probe. Otherwise make a same-origin `only-if-cached` probe while the stage remains empty: do not display the low-resolution thumbnail or progress during this check. A browser-cache hit must decode/display the full image without either flash, while a miss/failure starts the cancellable original request. Before its body transfers, `ViewFile` identifies header metadata, applies EXIF orientation to its dimensions, and returns `X-Image-Width`/`X-Image-Height`; only then start the existing Gallery thumbnail and size its element to the exact no-upscale viewport-fit rectangle calculated from those original dimensions. This makes replacement change sharpness rather than dimensions for large, small, portrait, and landscape sources. If metadata is unavailable, fall back to the configured thumbnail-bound heuristic. Keep placeholder sizing on viewport resize and disable placeholder zoom. The request overlay shows percentage and human-readable loaded bytes / total bytes from `Content-Length`. The cache-only probe must never contact the network. Navigating or closing the viewer aborts the probe/request and invalidates late results, but page-memory full images remain available until LRU eviction or `pagehide`; revoke Blob URLs only on eviction/replacement/pagehide. Suspend ordinary Gallery thumbnail requests while the viewer is open and resume visible requests after it closes so the requested image remains responsive.
- The full-image viewer navigates only among image files in the current rendered folder order. Provide slim previous/next controls at the left and right edges and support the keyboard Left/Right arrow keys. Navigation wraps from the last image to the first and from the first to the last; hide the controls when fewer than two images are available.
- When the Back card navigates to a parent folder, carry the child folder path as a focus target. The parent page must scroll that folder card into view and briefly highlight it instead of returning the user to the top of the listing. Apply this in private and shared views.
- Let the site header scroll out of view with the page. Keep the Gallery toolbar sticky at the top edge (`top: 0`) so sorting, Grid density, Grid/List switching, and selected downloads remain available while scrolling.
- The first-use Grid default is 8 items per row. Preserve the user's later Grid density and Grid/List choice in browser local storage. Preserve the last valid sort field (`name`, `size`, or `date`) and direction (`asc` or `desc`) in application-scoped, one-year cookies; when a Gallery/Share request omits sort parameters, restore those cookies before falling back to name ascending.
- Admin users manage system settings, users, roles, passwords, and user root folders. Standard users browse their own private root and create or revoke scoped share links.
- The Admin system settings page manages `AppTitle`, system `Theme` (`retro` or `modern`), and the runtime thumbnail concurrency limit. Persist them as SQLite app settings; update the live thumbnail dispatcher immediately after save. Invalid theme values must be rejected, and missing/unknown stored values must safely fall back to `retro`.
- A configured user root must already exist and be enumerable by the IIS worker identity. Validate access during Admin save and show a useful error instead of allowing a later Gallery 500.
- For roots inside a Windows user profile or OneDrive, grant `IIS_IUSRS` only the required Read & Execute permission on the selected root and descendants. Do not grant write/delete permission merely for gallery browsing.
- OneDrive gallery content should be marked **Always keep on this device**; an IIS worker cannot reliably serve cloud-only placeholders when the interactive OneDrive session is unavailable.
- A fresh database creates `admin` with a random password in `C:\Web\imagegallery-data\bootstrap-admin.txt`. Never commit or place a bootstrap password in source configuration.
- Protect the application Login POST with two complementary cooldowns: ASP.NET Identity persistently locks a real account after 5 failures for 15 minutes, while a bounded in-memory limiter blocks 5 failures per normalized username for 15 minutes and 12 failures per client IP for 5 minutes. Return the styled Login view with HTTP 429, a `Retry-After` header, and a visible countdown; keep the message generic to avoid confirming whether an account exists. Successful authentication clears the current username/IP buckets. Use the direct connection IP unless a reverse proxy is deliberately configured with trusted forwarded-header processing; never trust arbitrary client-supplied forwarding headers.
- Protect the public Share entry-point from token enumeration. Invalid, malformed, missing, or revoked tokens count case-insensitively by direct client IP; attempts 1-19 return the same 404, while attempt 20 within a sliding 5-minute window starts a 5-minute cooldown. During cooldown return the themed HTTP 429 page with `Retry-After` and the shared countdown UI before querying SQLite. Keep the bounded limiter keys hashed and do not reveal whether a particular token existed. A valid token with an out-of-scope path remains a normal 404 and does not count as token guessing.

## IIS requirements

- The `/Gallery` IIS application must allow Anonymous Authentication and disable Basic Authentication so ASP.NET Core can enforce login-protected galleries and token-based share links itself.
- IIS authentication settings are locked at server level on the current machine and cannot be overridden in `web.config`; change them for the `/Gallery` application with IIS Manager or elevated `appcmd`.
